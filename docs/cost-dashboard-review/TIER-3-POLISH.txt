9. RESPONSIVE DESIGN - Fix Mobile & Tablet Breakpoints
================================================================================

PROBLEM:
  Several components have fixed widths or missing intermediate breakpoints that
  cause layout issues on mobile and tablet devices.

AFFECTED FILES & SPECIFIC LOCATIONS:

  app/components/costs/CostsSummaryCards.vue
    - Line 2: Grid uses `grid-cols-1 md:grid-cols-4` but no `sm:grid-cols-2`
    - On tablets (640-768px), cards stack vertically instead of showing 2 per row
    - Fix: Change to `grid-cols-1 sm:grid-cols-2 lg:grid-cols-4`

  app/components/costs/CostDataTable.vue
    - Line 10: UInput with `class="w-64"` doesn't shrink on mobile
    - Search input overflows the container on small screens
    - Fix: Change to `class="w-full sm:w-64"`

  app/components/costs/CostsHeader.vue
    - Lines 26-66: Multiple buttons in header row wrap awkwardly on small screens
    - No responsive stacking or overflow handling
    - Fix: Add `class="flex flex-wrap gap-2"` and consider collapsing into
      dropdown menu on mobile:
      ```vue
      <!-- Mobile: Show overflow menu -->
      <UDropdown :items="headerActions" class="sm:hidden">
        <UButton icon="i-heroicons-ellipsis-vertical" variant="ghost" />
      </UDropdown>

      <!-- Desktop: Show all buttons -->
      <div class="hidden sm:flex items-center gap-2">
        <!-- existing buttons -->
      </div>
      ```

  app/components/costs/ChartsRenderer.vue
    - Chart grid layout: full-width charts work well, but medium (2-col) charts
      should stack on mobile
    - Verify: `grid-cols-1 md:grid-cols-2` pattern is used for medium charts
    - Chart height classes (h-96, h-80, h-64) are fixed - consider making
      chart heights responsive:
      ```
      h-64 sm:h-72 md:h-80 lg:h-96
      ```

  app/components/costs/CostSettings.vue
    - Line 14: Popover width is `w-80` (320px) - fine on desktop but may be
      too wide on very small mobile screens
    - Fix: `w-72 sm:w-80` or use `max-w-[calc(100vw-2rem)]`

ADDITIONAL RESPONSIVE CONSIDERATIONS:
  - Summary card values with long currency strings may overflow on small screens
  - Data table column count may need horizontal scrolling on mobile
  - Chart tooltips may be clipped on small viewports (ECharts confine option)
    ```typescript
    tooltip: { confine: true }  // Keeps tooltip within chart bounds
    ```

ESTIMATED EFFORT: 0.5-1 day
RISK: Very low (CSS-only changes)
TESTING: Use browser DevTools responsive mode at: 320px, 640px, 768px, 1024px, 1280px

10. ARIA LABELS & ACCESSIBILITY - Screen Reader & Keyboard Support
================================================================================

PROBLEM:
  Multiple components lack ARIA attributes, making the dashboard inaccessible
  to users relying on screen readers or keyboard navigation.

AFFECTED FILES & SPECIFIC LOCATIONS:

  app/components/costs/ChartsRenderer.vue
    - Lines 58-60: Loading spinner has no aria-label or role
    - Charts render via ECharts without ARIA labels or alt text
    - Fix for spinner:
      ```vue
      <div role="status" aria-live="polite" aria-label="Loading chart data">
        <UIcon name="i-heroicons-arrow-path" class="animate-spin" />
        <span class="sr-only">Loading chart data...</span>
      </div>
      ```
    - Fix for charts: ECharts supports built-in ARIA
      ```typescript
      // In chart builders or createBaseChartOptions()
      aria: {
        enabled: true,
        description: 'Cost breakdown chart showing spending by service'
      }
      ```

  app/components/costs/CostDataTable.vue
    - Lines 74-75: Sort indicators on column headers lack aria-sort attribute
    - Fix: Add `aria-sort="none|ascending|descending"` to sortable column headers
      ```vue
      <th :aria-sort="getSortState(column)">{{ column.label }}</th>
      ```
    - Lines 143-146: Empty state doesn't announce to screen readers
    - Fix: Add `aria-live="polite"` to empty state container

  app/components/costs/CostsHeader.vue
    - Line 63: Refresh button has UTooltip but no aria-label
    - Fix: Add `aria-label="Refresh cost data"` to button
    - Consider: All icon-only buttons need aria-label attributes

  app/utils/chart-options/line-trend.ts
    - Lines 116-131: Rich text formatting with `{weekend|...}` syntax is visual-only
    - Line 52: Emoji in axis labels ("Master Account") not accessible
    - Fix: Add plain-text aria descriptions alongside visual formatting

  app/utils/chart-options/service-cost-distribution.ts
    - Treemap has no keyboard navigation support
    - ECharts treemap is not keyboard-accessible by default
    - Fix: Add data table alternative for screen reader users (toggle between
      chart and accessible table view)
      ```vue
      <div role="tabpanel">
        <button @click="showAccessibleTable = !showAccessibleTable">
          {{ showAccessibleTable ? 'Show Chart' : 'Show Data Table' }}
        </button>
        <VChart v-if="!showAccessibleTable" ... />
        <table v-else role="table" aria-label="Service cost distribution">
          <!-- Accessible table version of treemap data -->
        </table>
      </div>
      ```

  General chart accessibility improvements:
    ```typescript
    // In createBaseChartOptions() - apply to ALL charts
    export function createBaseChartOptions(): EChartsOption {
      return {
        // ... existing options
        aria: {
          enabled: true,
          decal: {
            show: true  // Color-blind friendly patterns on bars/pie
          }
        }
      }
    }
    ```

  app/components/costs/CostDashboardAlerts.vue
    - Verify alert badges have screen reader text
    - Status badges (SENT, FAILED, PENDING) should have aria-label with context

WCAG 2.1 AA CHECKLIST FOR THIS DASHBOARD:
  [ ] All interactive elements keyboard-accessible
  [ ] All images/charts have text alternatives
  [ ] Color is not the sole means of conveying information
  [ ] Loading states announced to assistive technology
  [ ] Focus management on modal open/close
  [ ] Sufficient color contrast (4.5:1 for text)
  [ ] Form inputs have associated labels

ESTIMATED EFFORT: 1-2 days
RISK: Very low (additive attributes, no behavior changes)
TESTING: Use browser accessibility audit (Lighthouse, axe); test with
  screen reader (NVDA on Windows); verify keyboard tab order through
  entire dashboard flow

================================================================================

  CostDataTable.vue allows users to select which columns are visible, but
  the selection resets on component remount (page navigation, refresh).

AFFECTED FILES & SPECIFIC LOCATIONS:

  app/components/costs/CostDataTable.vue
    - Line 272: Column selection state (local ref, not persisted)

WHAT TO DO:

  Option A: Add to existing useCostSettingsStore
    ```typescript
    // In app/stores/useCostSettingsStore.ts
    interface CostFilterSettings {
      // ... existing fields
      visibleTableColumns?: string[]  // Column IDs to show
    }
    ```
    - Automatically persisted via pinia-plugin-persistedstate
    - Centralized with other cost preferences

  Option B: Use localStorage directly in component
    ```typescript
    const COLUMN_STORAGE_KEY = 'ghost-cost-table-columns'
    const savedColumns = localStorage.getItem(COLUMN_STORAGE_KEY)
    const selectedColumns = ref<string[]>(
      savedColumns ? JSON.parse(savedColumns) : defaultColumns
    )

    watch(selectedColumns, (cols) => {
      localStorage.setItem(COLUMN_STORAGE_KEY, JSON.stringify(cols))
    }, { deep: true })
    ```

  Recommendation: Option A (store) for consistency with other settings

ESTIMATED EFFORT: 30 minutes
RISK: Very low

16. STANDARDIZE BUTTON STYLING PATTERNS
================================================================================

PROBLEM:
  Buttons across cost components use inconsistent color/variant combinations.
  No clear pattern for which actions get which style.

OBSERVED PATTERNS:
  - CostsHeader.vue: Reports uses `color="gray" variant="ghost"`
  - CostsHeader.vue: Help uses `color="gray" variant="ghost"`
  - CostDataTable.vue: Export uses `color="purple" variant="outline"`
  - Various: Primary actions use different colors

WHAT TO DO:

  Define a consistent button style guide for the cost dashboard:
    ```
    Primary actions (Export, Generate): color="primary" variant="solid"
    Secondary actions (Share, Reports): color="gray" variant="outline"
    Tertiary actions (Help, Settings):  color="gray" variant="ghost"
    Danger actions (Clear, Remove):     color="red" variant="outline"
    Icon-only actions (Refresh, Close): color="gray" variant="ghost" + aria-label
    ```

  Apply consistently across:
    - CostsHeader.vue (all header buttons)
    - CostDataTable.vue (table action buttons)
    - CostSettings.vue (settings actions)
    - CostDashboardAlerts.vue (alert actions)

ESTIMATED EFFORT: 1-2 hours
RISK: Very low (visual consistency)
