17. APPLY COST THRESHOLD FILTER TO CHARTS (Not Just Sidebar)
================================================================================

PROBLEM:
  When users set a minimum cost threshold in settings (e.g., $1,000), the sidebar
  account list correctly hides low-cost accounts. However, chart data still
  includes ALL accounts regardless of the threshold setting. This creates an
  inconsistency where the sidebar shows 10 accounts but charts aggregate 50.

AFFECTED FILES:
  - app/components/costs/CostSettings.vue lines 82-96 (sets threshold)
  - app/composables/useChartRegistry.ts (extractors don't read threshold)
  - app/components/costs/ChartsRenderer.vue (renders whatever extractors return)

IMPLEMENTATION APPROACH:

  Step 1: Pass filter settings through to chart context
    ```typescript
    // In ChartsRenderer.vue or parent
    const context = computed<ChartBuilderContext>(() => ({
      // ... existing context
      filters: {
        minCostThreshold: costSettings.minCostThreshold,
        hideDecommissioned: costSettings.hideDecommissioned,
        hideSavingsPlans: costSettings.hideSavingsPlans,
      }
    }))
    ```

  Step 2: Update extractors to respect filters
    ```typescript
    // In each extractor that aggregates account data
    function extractAccountData(dataset: NormalizedDataset, context: ChartBuilderContext) {
      let accounts = dataset.accountsList || []

      // Apply threshold filter
      if (context.filters?.minCostThreshold > 0) {
        accounts = accounts.filter(a =>
          (a.totalCost || 0) >= context.filters.minCostThreshold
        )
      }

      // Apply decommissioned filter
      if (context.filters?.hideDecommissioned) {
        accounts = accounts.filter(a => !a.isDecommissioned)
      }

      // ... rest of extraction
    }
    ```

  Step 3: Add "Filtered" indicator on charts when filters are active
    ```vue
    <div v-if="activeFilterCount > 0" class="text-xs text-gray-400 mb-1">
      Showing filtered data ({{ activeFilterCount }} filter(s) active)
    </div>
    ```

CONSIDERATIONS:
  - Some charts (like total spend trend) should probably NOT filter (show full picture)
  - Add per-chart flag: `respectsThresholdFilter: boolean`
  - Service-level charts may need different filtering than account-level

ESTIMATED EFFORT: 1-2 days
COMPLEXITY: Medium

18. WHAT-IF SCENARIO MODELING
================================================================================

PROBLEM:
  The current useCostScenario.ts (39 lines) only detects whether the user is
  viewing single vs multiple accounts. There's no ability to simulate spending
  changes like "What if we reduce EC2 spending by 20%?" or "What if we remove
  this account?"

PROPOSED FEATURE:

  A scenario modeling panel that lets users:
  1. Adjust spending by percentage for specific services
  2. Remove/add accounts from projection
  3. Apply growth rate assumptions
  4. Compare "as-is" vs "to-be" projections side by side

IMPLEMENTATION APPROACH:

  Step 1: Define scenario model
    ```typescript
    // app/types/cost-scenario.ts
    interface CostScenario {
      id: string
      name: string
      baselineTimeframe: string  // 'thisMonth' | 'last30days' | etc
      adjustments: ScenarioAdjustment[]
      createdAt: Date
    }

    interface ScenarioAdjustment {
      type: 'service-percent' | 'account-remove' | 'account-add' | 'growth-rate'
      target: string              // Service name or account ID
      value: number               // Percentage change or growth rate
      description?: string
    }
    ```

  Step 2: Create scenario composable
    ```typescript
    // app/composables/useCostScenarioModeling.ts
    export function useCostScenarioModeling(dataset: Ref<NormalizedDataset>) {
      const scenarios = ref<CostScenario[]>([])
      const activeScenario = ref<CostScenario | null>(null)

      function applyScenario(scenario: CostScenario): NormalizedDataset {
        const modified = deepClone(dataset.value)
        for (const adj of scenario.adjustments) {
          switch (adj.type) {
            case 'service-percent':
              applyServiceAdjustment(modified, adj.target, adj.value)
              break
            case 'account-remove':
              removeAccountFromDataset(modified, adj.target)
              break
            case 'growth-rate':
              applyGrowthRate(modified, adj.value)
              break
          }
        }
        return modified
      }

      function compareScenarios(baseline: NormalizedDataset, modified: NormalizedDataset) {
        return {
          totalSavings: baseline.totalSpend - modified.totalSpend,
          percentChange: ((modified.totalSpend - baseline.totalSpend) / baseline.totalSpend) * 100,
          affectedAccounts: getAffectedAccounts(baseline, modified),
          affectedServices: getAffectedServices(baseline, modified),
        }
      }

      return { scenarios, activeScenario, applyScenario, compareScenarios }
    }
    ```

  Step 3: Create UI component
    ```vue
    <!-- app/components/costs/CostScenarioPanel.vue -->
    <UCard>
      <template #header>
        <div class="flex justify-between items-center">
          <h3>What-If Analysis</h3>
          <UButton @click="addScenario">New Scenario</UButton>
        </div>
      </template>

      <!-- Adjustment builder -->
      <div v-for="adj in activeScenario.adjustments" :key="adj.id">
        <USelectMenu v-model="adj.type" :options="adjustmentTypes" />
        <USelectMenu v-model="adj.target" :options="availableTargets" />
        <UInput v-model="adj.value" type="number" suffix="%" />
      </div>

      <!-- Comparison summary -->
      <div v-if="comparison" class="mt-4">
        <div class="text-lg font-semibold">
          Projected Savings: {{ formatCurrency(comparison.totalSavings) }}
          ({{ comparison.percentChange.toFixed(1) }}%)
        </div>
      </div>
    </UCard>
    ```

  Step 4: Add comparison chart that overlays baseline vs scenario
    ```typescript
    // New chart builder: scenario-comparison
    // Shows two overlapping area charts: baseline (blue) and scenario (green)
    ```

CONSIDERATIONS:
  - Scenarios should be saveable (localStorage or API)
  - Share scenarios via URL parameters
  - Export scenario comparison as PDF
  - Consider "templates" for common scenarios (e.g., "Optimize Reserved Instances")

ESTIMATED EFFORT: 3-5 days
COMPLEXITY: High
PREREQUISITE: Tier 1 type safety, Tier 2 API normalization

21. COST OPTIMIZATION RECOMMENDATIONS
================================================================================

PROBLEM:
  The dashboard is observational, not prescriptive. It shows what is being
  spent but doesn't suggest how to reduce costs.

PROPOSED FEATURE:

  An "Optimization Insights" section that analyzes spending patterns and
  suggests actionable cost reduction strategies.

POSSIBLE INSIGHTS:

  1. Reserved Instance Coverage
     - "Account X has 0% RI coverage on EC2. Estimated savings with 1-year RI: $X,XXX/month"
     - Requires: EC2 usage data, RI pricing

  2. Savings Plan Utilization
     - "Your Compute Savings Plan is only 60% utilized. Consider downsizing commitment."
     - Requires: Savings Plan usage data

  3. Idle Resource Detection
     - "3 EC2 instances in Account Y have <5% CPU utilization over 30 days"
     - Requires: CloudWatch metrics integration

  4. Service Consolidation
     - "Account X and Account Y both run similar workloads. Consider consolidation."
     - Requires: Resource inventory comparison

  5. Spend Velocity Warnings
     - "Account Z's daily spend has increased 40% this week. Investigate possible cause."
     - Requires: Anomaly detection (Feature #19)

IMPLEMENTATION APPROACH:

22. REQUEST PROGRESS TRACKING
================================================================================

PROBLEM:
  During the multi-phase data loading, users see a generic loading spinner but
  don't know how many requests are in flight or how far along the load is.

PROPOSED FEATURE:
  Show "Loading 3 of 5 data sources..." or a progress bar during initial fetch.

IMPLEMENTATION APPROACH:

  Step 1: Add progress tracking to useCostData.ts
    ```typescript
    const fetchProgress = reactive({
      total: 0,
      completed: 0,
      currentPhase: '' as 'core' | 'deferred-1' | 'deferred-2' | ''
    })

    // In fetchCosts():
    fetchProgress.total = 11  // Total API calls
    fetchProgress.completed = 0
    fetchProgress.currentPhase = 'core'

    // After each successful fetch:
    fetchProgress.completed++
    ```

  Step 2: Expose progress in composable return
    ```typescript
    return {
      // ... existing
      fetchProgress: readonly(fetchProgress)
    }
    ```

  Step 3: UI progress indicator
    ```vue
    <div v-if="isFetching" class="flex items-center gap-2">
      <UProgress :value="progressPercent" size="sm" class="w-32" />
      <span class="text-xs text-gray-500">
        Loading {{ fetchProgress.completed }}/{{ fetchProgress.total }}...
      </span>
    </div>
    ```

ESTIMATED EFFORT: 2-4 hours
COMPLEXITY: Low

25. CUSTOM DATE RANGE PICKER
================================================================================

PROBLEM:
  The timeframe selector offers preset options (thisMonth, last30days, etc.)
  but no custom date range picker for specific analysis periods.

PROPOSED FEATURE:
  Add "Custom Range" option to timeframe selector that opens a date picker
  allowing start and end date selection.

  ```vue
  <UPopover v-if="selectedTimeframe === 'custom'">
    <div class="p-4 space-y-4">
      <div>
        <label>Start Date</label>
        <UInput type="date" v-model="customStart" :max="customEnd || today" />
      </div>
      <div>
        <label>End Date</label>
        <UInput type="date" v-model="customEnd" :min="customStart" :max="today" />
      </div>
      <UButton @click="applyCustomRange">Apply</UButton>
    </div>
  </UPopover>
  ```

CONSIDERATIONS:
  - AWS Cost Explorer has a 12-month lookback limit
  - Custom ranges affect cache key generation
  - May need server-side validation of date range limits

ESTIMATED EFFORT: 1-2 days
COMPLEXITY: Medium
