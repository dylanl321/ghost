# GHOST Server

The Nitro server behind GHOST. It serves the internal API used by the
dashboard, the supported `/api/v1` integration API, and the hosted MCP server.
It reads AWS data across the Commercial and GovCloud partitions through
cross-account role assumption, with DynamoDB for GHOST's own state.

Setup, commands and tests are covered in
[`docs/DEVELOPER_GUIDE.md`](../docs/DEVELOPER_GUIDE.md). This file covers
server conventions.

## Layout

```
server/
├── api/            File-based API routes: <path>.<method>.ts → /api/<path>
│   └── v1/         Supported integration contract (API keys only)
├── routes/         Non-/api routes: /mcp and the MCP OAuth endpoints
├── middleware/     00-request-timing.ts, entra-auth.ts (authentication, admin gate)
├── plugins/        Swagger, report scheduler, OAuth loops, dataset export worker, login tracking
├── mcp/            MCP server, tools, policy, rate limits and OAuth implementation
├── kirocrew/       Kiro Crew collaboration runtime
├── lib/            aws-client-factory.ts, config.ts, dynamodb-config.ts, shortlinks.ts, account-notes.ts
├── utils/          Auto-imported server utilities; unit tests in utils/__tests__/
├── types/          Server TypeScript types
└── generated/      swagger-routes.ts, generated by scripts/generate-swagger-registry.ts
```

## Authentication

`middleware/entra-auth.ts` runs before every route:

- Internal `/api/*` routes require an Entra ID session (`nuxt-oidc-auth`).
- `/api/v1/*` accepts API keys only, in the `x-api-key` header, and errors use
  the v1 envelope from `utils/v1-errors.ts`.
- Every `/api/admin/*` route requires the Administrator role, apart from a
  short allowlist in the middleware. Finer-grained checks belong in handlers.
- `/mcp` uses the MCP OAuth token verifier in `mcp/oauth/`.

## Writing an endpoint

```typescript
// server/api/example/summary.get.ts
import { defineEventHandler, getQuery } from 'h3'
import { sendSuccess, errors, handleAsync, validateEnvironment } from '../../utils/api-response'
import { registerEndpoint } from '../../plugins/swagger'

registerEndpoint('/api/example/summary', 'GET', {
  summary: 'Example summary',
  description: 'What the endpoint returns and when to use it',
  tags: ['Example'],
  parameters: [{ $ref: '#/components/parameters/Environment' }],
  responses: { 200: { description: 'Summary' } }
})

export default defineEventHandler(handleAsync(async (event) => {
  const environment = String(getQuery(event).environment ?? 'govcloud')
  if (!validateEnvironment(environment)) return errors.badRequest(event, 'environment must be commercial or govcloud')
  return sendSuccess(event, { environment })
}))
```

- Only route files that call `registerEndpoint` (or `defineV1Alias`) are
  picked up by `npm run swagger:prepare` and appear in Swagger.
- Shared OpenAPI parameters (`Environment`, `AccountIdentifier`, …) live in
  `utils/swagger-parameters.ts`.
- Validate input with zod 4 or the helpers in `utils/api-response.ts`, and
  clamp numeric query parameters.

API documentation while the server runs:

- Swagger UI: `/api/swagger-ui` (OpenAPI JSON at `/api/swagger.json`)
- Internal route reference: `/api/swagger-internal-ui` (`/api/swagger-internal.json`)

## AWS clients

Always create clients through `lib/aws-client-factory.ts` so credentials,
partition selection, cross-account role assumption and caching are handled in
one place:

```typescript
import { getClient, getDynamoDBClient, getOrganizationsClient } from '../lib/aws-client-factory'

const dynamo = await getDynamoDBClient('commercial')            // or 'govcloud'
const ec2 = await getClient('govcloud', 'ec2', 'us-gov-west-1', '123456789012') // member account
const org = await getOrganizationsClient('commercial')          // management account
```

Athena queries (Security Lake and pipeline data) go through
`utils/athena-query.ts`.

## Error envelope

Internal routes return:

```json
{
  "success": false,
  "error": { "code": "ERROR_CODE", "message": "Human-readable message", "details": {} },
  "metadata": { "timestamp": "2026-01-01T00:00:00.000Z" }
}
```

`/api/v1/*` routes use the v1 envelope in `utils/v1-errors.ts`.

## Trying endpoints locally

With `npm run dev` running and a signed-in browser session, use Swagger UI.
For the v1 API with an API key:

```bash
curl http://localhost:3000/api/health
curl -H "x-api-key: $GHOST_API_KEY" http://localhost:3000/api/v1/accounts
curl -H "x-api-key: $GHOST_API_KEY" "http://localhost:3000/api/v1/costs/summary?startDate=2026-01-01&endDate=2026-01-31"
```

## Security checklist for new routes

- Never commit `.env` files or credentials.
- Validate and bound every input; never pass raw input into Athena SQL,
  DynamoDB expressions or AWS ARNs without validation.
- Check permissions in the handler for anything beyond the central admin gate.
- Keep secrets and tokens out of logs; use `logger`, and bound untrusted values with `boundedLogField`.
- Use least-privilege IAM; new AWS permissions go in `terraform/iam.tf`.
